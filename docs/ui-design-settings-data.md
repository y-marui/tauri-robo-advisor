# UI Design: Settings, Data Folder and Records

[ui-design.md](ui-design.md) の一部。[ui-design-settings.md](ui-design-settings.md) から切り出した、設定タブの保存先、Records、Groups、Settings Tab、Accounts のカードを扱う。

## Data Folder Card

設定タブの、設定のカードの次に置く。

- 今のデータの保存場所（このコンピューターだけか、選んだフォルダか）を示す。フォルダのフルパスを入れて「このフォルダを使う」、iCloud Drive が使えるコンピューターでは「iCloud Drive のフォルダを使う」、選んだ後は「このコンピューターのフォルダに戻す」。
- 移す先にすでにデータがあるときは、「そのフォルダのデータを使う」かキャンセルかを聞く。
- 同期が作った競合のコピー、未ダウンロードのファイル、使えなかった新しいファイルは、画面の上に知らせる。

## Records Card

設定タブの「全レコード」。商品とレコード（口座 × 商品の 1 行）を、保存されているままに編集する場所（保有タブの表は表示だけ）。カテゴリとグループの名前は、設定タブの「カテゴリ」と「グループ」のカードで編集する（カードの説明に書いてある。保有タブのボタンは、このカードへ案内する）。

- 1 つの表。カテゴリの見出し行のあとに、商品ごとの `<tbody>` が並ぶ。商品の見出し行には、商品名（名前の長さに合わせて入力欄が広がり、全文がツールチップにも出る。親要素の幅が上限）、カテゴリの選択、通貨、「商品を削除」（2 回クリック。商品のレコードも消える）、「レコードを追加」のミニフォーム（口座の選択、種別、金額。金額は必須）を置く。幅が狭いと折り返す。
- 商品の見出し行の末尾に折りたたみ「統合・分割」を置く。「統合」: 同じ通貨の別の商品を統合先に選び（選択肢は幅を切らず、名前の全文を出す）、両方の商品に同じ口座のレコードがあるときにどちらを残すか（既定は統合先のレコード）を選ぶ。「分割」: 別名を 1 つ選び、新しい商品の名前を入れ、一緒に移すレコードの口座にチェックを入れる。
- 商品の見出し行の先頭にチェックボックスを置き、表の上のバーで一括設定する。「表示中をすべて選択」（絞り込み中は見えている商品だけ）、「選択を解除」、「このカテゴリの商品を選択」（商品は必ずカテゴリを持つため、「カテゴリなし」の選択はない。取り込み後の受け皿カテゴリの商品をまとめて選ぶのに使う）、選択件数の表示。設定先は既存のカテゴリか「新しいカテゴリ...」（名前を入力）で、「選択した商品に設定」で 1 回の編集（保存 1 回、取り消し 1 回）として反映する。成功すると選択は解除される。取り込み画面は変えない。
- その下に、レコードの行を口座の順に並べる。列は 口座、種別、数量（表示のみ）、価格（表示のみ。単位つき）、金額（入力欄と商品の通貨）、削除（2 回クリック）。レコードのない商品は「レコードはありません」と出す。
- 金額を空にしてもレコードは消えない（数値を求める表示を出し、元の値に戻す）。消すのは削除ボタンだけ。0 にするときは 0 を入れる。商品の比率（カテゴリ内の持ち方）は、ここではなくリバランスのタブで編集する。
- 表の下に、商品の追加フォーム（名前、カテゴリ、通貨）。現金は通貨ごとの商品として同じ手順で作る。
- カードの見出しの下に、商品名の絞り込み欄を置く（表の再構築の外にあるので、編集や追加で消えない。行を隠すだけ）。
- 追加のあとの再構築でフォーカスが落ちないよう、追加したレコードの商品のフォーム（または商品の追加フォーム）へフォーカスを戻す。
- 別名は表示しない（別名は取り込みの対応づけの画面で扱う）。

## Groups Card

設定タブで、カテゴリのカードの前に置く。グループの名前の一覧（その場で名前を変えられる。左端のつかみ（⋮⋮）をドラッグして並び順を変える。上へ・下へのボタンも残す。端のボタンは無効。削除は 2 回のクリックで、カテゴリは残る）。追加の欄は一覧と同じ表の最後の行で、名前の欄は名前の列、「追加」は削除ボタンの列（右端）に置く。グループがあるとき、カテゴリのカードに「グループ」の選択（先頭は「グループなし」）の列が出る。

## Settings Tab

設定タブにある画面で、グループ・カテゴリ・商品・レコード・口座・設定を手入力する。

- 1 列に、グループ、カテゴリ、口座、全レコード、設定、データの保存場所のカードを並べる（作業する順）。グループ・カテゴリ・口座の行は、左端のつかみ（⋮⋮）をドラッグして好きな位置へ 1 回で動かせる（ポインタイベントで実装し、共有部品は `src/sortable.ts`。ドラッグ中の行は薄くなり、落とす位置に線が出る。Esc で取り消す。動かした行は、並べ替えのあと約 1.5 秒ハイライトされる。上へ・下へのボタンで動かしたときも同じ）。上へ・下へのボタンも残す（キーボード操作の代わり）。並び順は保存され、グラフの色・表・選択肢の順に使われる。グループ・カテゴリ・口座の一覧は、列を内容の幅にして左に詰める（カードの幅いっぱいに広げない）。各一覧の追加の行は同じ表の最後の行（つかみの列は空）で、入力欄は上の行の同じ列の真下に並び、「追加」は削除ボタンの列に置く（入力欄は表の外の空の form に `form` 属性で結ぶ）。表は、カードの中で横にスクロールできる。
- 入力欄は、値を確定したとき（Enter かフォーカス移動）に 1 つの編集として Rust へ送る。保存に成功すると、表示を更新する。失敗したときは、理由を表示し、入力欄を元の値に戻す。保存のあとも、フォーカスと Tab の順は保たれる。
- 比率は「%」で入力し、Rust には正確な小数（例: 30 → 0.3）で送る。計算には浮動小数点を使わない。
- 削除は 2 回のクリックで実行する（1 回目で確認の表示に変わり、数秒以内の 2 回目で削除する）。`window.confirm` は Tauri の WebView で信頼できないため使わない。
- 提案をブロックする不備（カテゴリの合計が 100% でない、など）は、画面の上に一覧で出す。
- 言語は、英語と日本語を切り替えられ、選んだ言語はブラウザの保存領域に覚える。保存領域が使えなくても動く。

## Accounts Card

- 「口座の種類」のカードは、標準の種別（名前は固定）を「標準の種類」の表に、追加した種別を「追加した種類」の表に出し、どちらにも「売却可」のチェックを置く（`SetTypeSellable`。標準の種別の現在の値は `get_portfolio` の `builtin_type_sellable`）。追加した種別は名前の変更と削除もでき、下に追加のフォームを置く。
- 口座の表は、名前・戦略・並べ替えと削除だけを持つ。「売却可」、丸め単位、売買に加える商品は、リバランスのタブで編集する（ui-design.md）。
- 口座の表の名前の右に「戦略」を置く（折りたたみ）。選択は「ポートフォリオに従う」（既定）と「商品と比率を指定」。後者を選ぶと商品の一覧を出し、商品にチェックを付けて、右の欄に比率を手で入力する（空欄 = 等分。全商品を空欄にするか全商品に入力する。混在はエラー）。編集は下書きで、「戦略を保存」を押すまで保存しない（途中の不整合な状態を保存しないため）。下書きが整合していない間はボタンを押せず、理由（商品が 0 件、比率の一部だけ空欄、数でない・0 以下）を表示する。保存は `SetStrategy`で、Rust の検証のエラーはそのまま表示する。「ポートフォリオに従う」への切り替えはすぐ保存する。
