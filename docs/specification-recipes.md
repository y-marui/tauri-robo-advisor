# Specification: Fetch Recipes

[specification.md](specification.md) の一部。取得レシピ（ログイン後の取得の自動化）を扱う。組み込みのレシピと反映は [specification-presets.md](specification-presets.md)。

## Fetch Recipes

ログイン後に、ボタン1つで保有の表をまとめて取得する仕組み（#36）。証券会社ごとのコードは持たず、利用者が保存する「レシピ」で動く。

- **レシピ**: 名前、たどるリンク（見える文字。最大 5 つ）、表の先頭のセルの書き出し、値の通貨（空なら商品の通貨）、更新する口座、列の指定（取り込み元の名前を含む）。リンクには、行き先を表す**参照**を持てる。
- **読む表**: ページから読むのは、見えている表だけ。2 つの組に分ける。(1) **ほかの表を含まない表**、(2) **外側の表**（セルの中に表を持つ表で、その中の表がどれもさらに表を持たないもの。金額を小さな表に入れて見せるページがある）。それより深く入れ子になった表は、ページの配置用なので読まない。外側の表のセルは、中の表の文字をふくめた、セルの見える文字で読む。書き出しに合う表の選び方は、まず (1) から探し、合うものがなければ (2) から探す（以前読めたページは、これまでと同じ表を読む。外側の表が (1) の表と重複して読まれることはない）。2 つの組を合わせて 200 表までで、そのうち最大 20 表は外側の表のために取っておく（小さな表が多いページで、外側の表が押し出されないため）。超えたページは、「全体を読めたとは言えない」ものとして扱う。読む手順は、固定の 1 つのスクリプトで、選ぶ表が変わるだけ。リンクをたどる・クリックする規則は変わらない。
- **作り方**: 「表の取り込み」で一度手で取得して列を指定したあと、「レシピとして保存」でリンクの文字と表の書き出しを足す。表の書き出しは、ブラウザで取得した表の先頭のセルの文字が入る。
- **リンクのたどり方**（`crates/browser`、`follow_link`）: 開いているページの `<a>` から、見える文字が完全に一致するものを探し、検査した行き先へ**直接移動する**（リンクを押す動作はしない。押すと、ページがリンクに付けたスクリプトが動くため）。移動の直前に、文字・サイト・行き先（パス・クエリ・`#` 以降）がもう一度一致することを、ページの中で確かめる。
  - たどるのは、同じサイト（スキーム・ホスト・ポートが同じ。`https` のページから `http` のリンクへは行かない）の、実際の行き先（アドレス）を持つ通常のリンクだけ。**例外として、レシピに「許可するサイト」（`allowed_sites`。例: `example.co.jp`）を明示したときは、そのサイトの別のホスト（`www.example.co.jp` など）へのリンクもたどれる。** 条件は、(1) 許可するサイトが、レシピを始めたページのホストを含むこと（始めたページと無関係なサイトは、書いてあっても無効。自社のほかのホストにだけ行ける）、(2) 行き先が `https` で、ポートの指定がなく、ホストが許可するサイトの下にあること。リンクは `https://ホスト/…` の形で省略せずに書かれていなければならない（URL の標準 API は、ユーザー名・既定のポート・余分なスラッシュ・バックスラッシュ・タブや改行を黙って取り除くので、書かれたとおりの文字列で確かめ、それらが入ったものは信用しない）（`badexample.co.jp` や `example.co.jp.evil.test` は断る）、(3) 行き先のアドレスは、通常のリンクと同じ規則で判定すること。移動の直前に、行き先のサイトが、承認したものと完全に同じかをページの中でも確かめ、移動のあとは、着いたページのオリジンを確かめる。別のホストへのリンクの参照（指紋）には、ホストも含める。許可するサイトは、プリセットではデータとして指定し、レシピに最大 3 つ。許可するサイトは、確認済みの会社のドメイン（`portfolio::VETTED_SITES`。いまは `sbisec.co.jp`・`monex.co.jp`・`connect-sec.co.jp`・`rakuten-sec.co.jp`）だけを保存できる。多くの持ち主が共有するドメインを、禁止リストで除くやり方は、リストが完全にならないので採らない。足すときは、このリストの変更とレビューを通す。`javascript:`・`#` やアドレスのないリンクは、押すとページ自身のスクリプトが動き、移動だけだとは言い切れないので、たどらない。ボタン、フォーム、入力欄、スクリプトも扱わない。
  - 文字か行き先が、注文・売買・入出金・振替・解約・変更・更新・保存・編集・登録・削除・送信・ログアウトなどに見えるリンクは、押さない。閲覧を示す言葉があれば許す（文字は「照会」「履歴」「一覧」「余力」「残高」など。行き先は、パスの各区切り（`/` ごと）、クエリの各組（`&` ごと）、`#` 以降（ハッシュで画面を切り替えるページがあるため）を**別々に**判断する。言葉は 2 種類ある。**行為を示す言葉**（キャンセル・削除・送信・保存・変更・更新・編集・登録・解約・購入・売却…）は、閲覧の言葉が同じ部分にあっても許さない（`Cancel order history`、`deletehistory` は断る）。**注文や金額の言葉**（注文・入金・出金・振替・order・transfer・payment…）は、閲覧を示す言葉（照会・履歴・一覧・余力・inquiry・history・list・balance など）が同じ文字・同じ部分にあるときだけ許す。隣の区切りに閲覧の言葉があっても許さない。`edit`・`apply`・`send` は語の先頭にあるときだけ数える（`credit` は問題にしない）。例: 許す =「注文照会」「買付余力」、`/orderhistory/list`。許さない = `/transfer/history`、`/history/delete`、`/transfer?account=1`、`/page?action=cancel`）。判断の前に、`%xx` の符号化を（二重でも）元に戻す（`/trans%66er` は `/transfer`）。実際に移動するアドレスは元のままにする。
  - **メニューのクリック**（`click_menu_link`。大和コネクト証券のように、フォームの POST とスクリプトのリンクで動くサイト用）: リンクの `menu`（メニューの組の見出しの文字）と `heading`（クリックのあとに見えるべき最初の見出し）を持つレシピは、そのリンクを**クリック**する。押せるのは、確認済みのサイトの、ページ自身が扱うリンク（`javascript:`・`#`・アドレスなし）だけで、(1) レシピの許可するサイトが今のページのホストを含むこと、(2) 組の見出しの文字と項目の文字が、どちらも通常のリンクと同じ文字の規則を通ること（「出金指示」「買付注文」「ログアウト」などは断る）、(3) その組にその文字の項目がただ 1 つあること（複数なら押さない）、(4) 新しいタブを開く・ダウンロードするリンクでないこと、を満たすときに限る。押す前に、ページの中でも同じ確認をする。クリックはページ自身のスクリプトを動かし、それが移動だけを行うことは証明できないので、**クリックのあとに、同じオリジンで、最初の見出しが `heading` と同じことを確かめ、違えば残りのレシピを止める**。戻る操作はしない（POST で表示したページは戻しても復元できない）。タブは着いたページに残り、そのページがバッチの開始ページになる。1 つのレシピは、すべてクリックか、すべて通常のリンクかのどちらかで、混ぜない。
  - 同じ文字のリンクは、すべて調べて、行き先ごとに1つにまとめる。行き先が同じなら、複数あっても1つとして押す。行き先が違うときは、勝手に選ばず、利用者に選んでもらう。選んだ行き先は参照として保存する。保存した参照に合うリンクがなければ（ページが変わった）、別のリンクを押さずに止めて、選び直しを求める。
  - 参照として保存するのは、行き先（パスと、変わらないクエリと、`#` 以降）の**指紋**（短いハッシュ。`h:` で始まる 16 桁）だけで、アドレスそのものは保存しない。リンクが運ぶトークンや識別子が、データファイルに入らないようにするため。毎回変わる部分を見落として指紋が合わなくなっても、危険な方向には動かず、「リンクが変わりました」と止まって選び直しになる。選ぶ画面には、そのときだけ行き先の文字を見せる（保存しない）。参照のもとにするのは、行き先のパスと、変わらないクエリと、`#` 以降だけ（`%73ession` のように符号化された名前や値も、元に戻して判断する。`_SeqNo` のようなセッション番号、`session`・`token`・`time` などを含む名前、時刻（13 桁以上の数字）や長いトークン（24 桁以上の 16 進）は落とす。口座番号のような短い数字は、行き先の一部として残す）。行き先が 500 文字を超えるリンクは、検査できないので押さない。URL そのものは保存せず、移動にも使わない。
  - 移動したあとは、新しいページに替わって読み込みが終わるまで（最長約 18 秒）待つ。移動の前に、今のページに印を付けておき、その印が消えた（新しいページに替わった）こと、または、ページを読み込み直さずにアドレスだけが変わるページでは、アドレスが変わったことを確かめる。古いページが「読み込み済み」と答えている間は、先へ進まない。そのあと、ページの内容が一定時間（約 1.5 秒）変わらなくなるまで（最長約 8 秒）待ってから読む。読み込みが遅いページでは、表がまだ前の画面のものである可能性は残る（待ち時間で完全には防げない）。そのため、結果は反映の前に必ず利用者が確認する。どのレシピも、実行が終わる（成功・失敗・選択待ちのいずれでも）と、履歴を戻して開始したページに戻る。次のレシピは、いつも同じ開始ページから始まる。移動したあとは、着いたページが最初に探したページと同じサイト（オリジン）にあること、戻したあとは、開始したページと同じアドレスにあることを確かめる。違えば、残りのレシピを実行せずに止める。反映は、利用者に見せた計画（見せた時点のポートフォリオと結果の状態）に対してだけ受け付け、その後に別名・レシピ・結果が変わっていれば断る。
- **表の選び方**: 表の最初の行（セルを順に続けた 1 行）がレシピの書き出しで始まる表（空白と改行は比べるときに無視する）が、ちょうど 1 つあること。0 または複数ならエラー（書き出しをより具体的にする）。ページのすべての表が同じ見出しのセルで始まるときは、書き出しを後ろのセルまで続けて、見出しの行で表を見分ける（マネックスの投資信託）。
- **「すべて取得」**: ブラウザを開いて、利用者がログインしたあと、ページを選んで押すと、全レシピを順に実行する。各ページの上のナビゲーションから、どのページからでもたどれる前提。結果（対応づけ済み、未対応、除外した行）をまとめて見せ、未対応の名前は、取り込みと同じ画面で商品に対応づける。
  - **同じページかどうかの確かめ**: 「すべて取得」の中で、タブが、最初のレシピを始めたページのままかどうかは、**スキーム・ホスト・ポート・パス**だけで比べる。パスの各区間の `;` 以降（セッション識別子を運ぶサイトがある）、クエリ、`#` 以降は比べない（取得のたびに変わるサイトで、「ページが変わりました」と止まってしまうため）。別のパス・ホスト・ポートに移ったことは、これまでどおり検出して止める。限界として、同じパスでクエリだけで中身が変わるページへ移っても気づけない（そのときは、リンクの文字か表の書き出しが合わず、失敗側に倒れる）。リンクをたどったあと、始めたページへ戻れたかの確認は、アドレス全体の一致のまま。
