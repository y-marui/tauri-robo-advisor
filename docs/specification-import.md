# Specification: Import and Acquisition

[specification.md](specification.md) の一部。取得方法、表の取り込み、証券会社の出力、bitFlyer の残高を扱う。

## Acquisition Methods

| 対象 | 方式 | 状況 |
|---|---|---|
| 全口座共通 | 手入力（設定タブの「全レコード」で編集） | 基本の方式 |
| 表形式の取り込み | CSV ファイル、または画面の保有一覧をコピーして貼り付けたテキスト（タブ区切り）。取り込むたびに列の対応づけ（名称・評価額・数量など）を画面で指定し、取得元ごとに保存して次回から使う。文字コードは Shift-JIS と UTF-8 を自動判別する | 実装済み（下記） |
| bitFlyer | REST API。API キーは OS のキーチェーンに保存する | 残高取得は実装済み（下記）。証拠金の取得は未実装 |
| ブラウザ拡張 | ログイン済みのブラウザで資産ページを読み取り、ローカルのアプリへ渡す | 将来の選択肢。必要になった時点で設計する |

証券会社ごとの専用パーサーは作らない。会社ごとに形式が違い、版によって変わり、公開された仕様もないため、列の対応づけを利用者が指定する汎用の取り込みにする。例外として、実際のページの構造を確認した**組み込みのレシピ（プリセット）**を、コードではなくデータとして出荷する（[specification-recipes.md](specification-recipes.md) の「Fetch Recipes」）。取り込んだ名称は、商品の別名として保存する。未登録の名称は、利用者が既存の商品へ割り当てるか、新しい商品として登録する。名称の自動推測はしない。

### Table Import

実装は `crates/tabular`（読み取りと列の選択）、`portfolio::plan_import`（別名での対応づけ）、`ReplaceHoldings`（保有の置き換え）。画面の「表の取り込み」カードから使う。

- 入力は、CSV（またはタブ区切り）のファイル、または貼り付けたテキスト。ファイルは UTF-8（BOM の有無を問わない）か Shift-JIS で、どちらでもなければ、文字化けさせずにエラーにする。バイナリ（NUL を含む）も拒否する。区切りは、先頭の数行にタブがあればタブ、なければカンマ。引用符の中の区切り・改行・二重引用符（`""`）を扱う。
- 入力は信頼しない。サイズは 2 MiB、行は 20,000、列は 200、1 つのセルは 1,000 文字までで、超えたら読みの途中でも止める。不正な入力はエラーを返し、パニックしない。読み込んだ表は Rust が 1 つだけ保持し、画面へは先頭 30 行のプレビューだけを返す（表は編集や置き換えのたびに捨てず、読み直すか画面を作り直したときに破棄する）。
- 利用者は、名前の列、評価額の取り方、見出しの行数、1件あたりの行数を指定する。
  - **1件が複数行の表**: 証券会社の保有一覧には、1件の保有が 2 行にまたがるもの（1 行目に名前、2 行目に数量や価格）がある。「1件あたりの行数」（1〜10）と、名前がある行・数値がある行（その中での位置）を指定する。名前と数値は、別の行なら同じ列番号でもよい。
  - **評価額の取り方**: 1 つの列の値、または「数量 × 価格 ÷ 価格の単位」。画面に評価額の列がなく、数量と現在値だけがあるときに使う。このとき、数量と価格は保有に保存する（`quantity`、`price`、`price_unit`）。「評価額の列」を選んだときは、評価額はその列の値を使い、「記録する数量の列」（任意）を選べば、数量も保存する（価格は保存しない）。評価額は、数量 × 価格で計算するか、元の評価額の列を使うかのどちらかで、損益や前日比は扱わない。投信の基準価額は 1 万口あたりなので、単位は 1 または 10,000 から選ぶ。計算は Rust の十進数で行い、桁あふれは範囲外として除外する。外貨の表は、値の通貨に USD を選べば、設定の USD/JPY で円換算される。
  - **1つのセルに複数の値がある表**: 1 つのセルに、複数の値が改行（ページの `<br>`）で、名前ではさらにノーブレークスペースで区切られて入っていることがある（「銘柄コード／銘柄名」、「保有数量／売却可能数量／注文済数量」、「価格／日付」など）。名前・数量（評価額）・価格のそれぞれについて、何番目の値かを指定できる（0 から数える。保存は `name_part` / `value_part` / `price_part`）。指定しないときは、セル全体を読み、改行は空白にする。範囲は 0〜19。数値のセルでは、ノーブレークスペースは桁区切りなので、分けない。ブラウザから読む表でも、セル内の改行とノーブレークスペースは残す（表のタイトルの照合では、空白として扱う）。
  - **前後に文字がある数値**: 「123.45US$」や「150.25（10/15）」のように、数値のまわりに単位や注記がある場合は、「前後の文字を許す」（`loose_numbers`）を選ぶと、セルの中の最初の数値を読む（桁区切り、全角数字、直前の符号を含む）。数値がなければ、これまでと同じく除外する。選ばないときは、セル全体が数値でなければならない。
  - 表の途中の見出しや小計、区分のタイトルの行は、除外した行として理由つきで一覧に出る（先頭の見出しは見出しの行数で飛ばせる）。読めなかった行のあとは、1 行ずつ進めて記録の区切りを探し直すので、途中に 1 行の小計があっても、そのあとの保有は読める。指定は取り込み元の名前ごとに保存し（`SetImportMapping`）、次回から使う。形式が変わったら、列を指定し直すだけでよい。
- 評価額は、桁区切り、円・¥・$ の記号、全角数字、先頭の符号（▲・△ を含む）を読む。数値でない行（小計や見出しなど）、名前のない行、負の値や大きすぎる値の行は、除外して一覧に出す。黙って捨てない。
- 名前は、取り込み元の名前を `source` とする別名で商品に対応づける。自動で推測せず、利用者が選ぶ（bitFlyer と同じ画面部品）。まだ商品がない名前は、その場で商品にできる（`AddProductWithAlias`）: 商品名（既定は取り込んだ名前）、カテゴリ、通貨（既定は取り込みで選んだ通貨。「商品の通貨」のときは円）を選ぶと、商品を作って、同じ操作で別名を結びつける。両方が成功するか、何も変わらないかのどちらかで、商品名が重複しているなどで失敗したときに、作りかけの商品は残らない。カテゴリが 1 つもなければ、先にカテゴリを追加するよう案内する。値の通貨は、既定では対応づけた商品の通貨（商品の設定を優先する）。利用者が通貨を選んだときだけ、別の通貨の商品に対応づけられた名前を除外する。
- 「保有を置き換える」（2 回のクリック）で、選んだ口座の保有を、対応づけ済みの行だけに置き換える。数量と価格は、行にあれば保存する。同じ商品に複数の行（名前）が対応づけられたときは、評価額と数量を合算し、価格はすべて同じときだけ残す（行の価格が違う、または数量のない行があるときは、価格や数量を空にする）。

## bitFlyer Balances

`crates/bitflyer` が `GET /v1/me/getbalance` で残高を取得し、JPY 建ての保有（`rebalance::Holding`）へ変換する。

- API キーには「資産残高を取得」の権限だけを付ける。注文・出金などの権限は不要で、クライアントは `GET` しか送らない。
- 署名は `ACCESS-TIMESTAMP + GET + パス + 本文` の HMAC-SHA256（16 進）。
- 通信は固定の `https://api.bitflyer.com` のみ。リダイレクトは追従せず、タイムアウトと応答サイズの上限を設ける。
- JPY 以外の通貨は、公開 API の `GET /v1/ticker?product_code=<通貨>_JPY` の最終取引価格で評価する（認証情報は送らない）。残高 0 は除く。
- JPY 市場がない通貨（HTTP 400）は評価できないので、`unpriced` として一覧で返す。黙って捨てるとポートフォリオを誤って表示するため。
- 数値は JSON の文字列のまま十進数へ変換し、浮動小数点を通さない。
- API キーとシークレットは OS のキーチェーンにだけ保存し、フロントエンドへは返さない。エラーメッセージや `Debug` 出力にも含めない。
- フロントエンドから呼べるコマンド: `save_bitflyer_credentials`、`has_bitflyer_credentials`、`delete_bitflyer_credentials`、`fetch_bitflyer_holdings`。

### bitFlyer in the UI

画面の「bitFlyer」カードで、キーの保存・削除と、残高の取り込みを行う。

- キーとシークレットは入力欄（パスワード型）に入れて保存する。保存後は入力欄を空にし、再表示はできない。削除は 2 回のクリックで実行する。「資産残高の取得」の権限だけでキーを作るよう、画面に明記する。
- 残高の取得は、取得してから保有に反映するまで 2 段階にする。取得した通貨は、別名（`source` が `bitflyer`、名前が通貨コード）で商品に対応づける。対応づけは自動で推測せず、利用者が通貨ごとに商品を選び、その選択を別名として記憶する。`portfolio::plan_import`（読み取り専用の `plan_import` コマンド）が、対応づけ済み・未対応・円建てでない商品に対応づけられたもの、に分ける。
- 同じ商品に複数の通貨が対応づけられているときは、その商品の評価額に足し合わせる（商品は 1 行になる）。誤った対応づけは、一覧の「対応づけを外す」で別名を削除（`RemoveAlias`）して、未対応に戻せる。
- 同じ商品が 2 つ作られたときは、記録カードの「統合・分割」で 1 つにまとめる（`MergeProducts { keep, remove, on_conflict }`）。通貨が違う商品は統合できない。カテゴリは残す側のもの。`remove` の別名とレコードは `keep` に移り、`remove` は削除される。同じ口座に両方のレコードがあるときは足さず、`on_conflict`（`keep`: 残す側のレコード、`take`: 消す側のレコード）で選ぶ。別名の上限（50）を超える統合は拒否する。逆に、別名の結びつけを誤ったときは `SplitProduct { product, source, alias, name, accounts }` で、別名を 1 つ新しい商品として切り出す（カテゴリと通貨は元の商品と同じ）。レコードは取り込み元の名前を持たないため、一緒に移すレコードは口座で利用者が選ぶ。買える商品の指定がある口座では、新しい商品も買える。切り出した商品を元の商品に統合すれば元に戻る（`take` で捨てたレコードは戻らない）。
- 多数の商品のカテゴリは、記録カードで選択して一括で設定・変更する（`SetProductsCategory { products, category | new_category }`）。`category`（既存）と `new_category`（名前。同じ編集で作る）はどちらか一方だけ。商品の一覧が空、未知の商品・カテゴリ、両方または両方なし、カテゴリ名の規則違反（空・重複・上限）は拒否し、検証のあとで反映するので一部だけ適用されることはない。新しいカテゴリの目標比率は 0、グループなし。既存カテゴリのグループは変えない。スキーマ変更なし。
- 評価できなかった通貨（`unpriced`）と、円建てでない商品に対応づけられた通貨は、一覧で示して除外する。
- 「保有を置き換える」を押すと（2 回のクリック）、`ReplaceHoldings` の編集で、選んだ口座の保有を、対応づけ済みの残高だけに 1 回の保存で置き換える。その口座にあった、一覧にない保有は消える。数量と価格は、残高にあれば保存する（取引所の残高は数量を持つが、価格は保存しない）。
