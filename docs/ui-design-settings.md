# UI Design: Settings, Import and Fetch

[ui-design.md](ui-design.md) の一部。設定タブのカード（bitFlyer、Coincheck、GMO コイン、Binance、表の取り込み、ブラウザで取得、取得レシピ）を扱う。保存先、Records、Groups、Settings Tab、Accounts は [ui-design-settings-data.md](ui-design-settings-data.md)。

## bitFlyer Card

手入力の画面と同じ列に置く。上から、API キーの権限の注意（資産残高の取得だけ）、キーとシークレットの入力と保存・削除、残高の取り込みの順。

- キーは保存後に再表示せず、保存済みかどうかだけを示す。
- 取り込みは、口座を選んで「残高を取得」を押し、対応づけの結果（対応づけ済みの表、未対応の通貨ごとの商品の選択、除外される通貨）を見てから「保有を置き換える」を押す。口座の選択肢は、暗号資産の口座を先に並べる。
- 口座の隣で価格の基準を選ぶ（Lightning の最終取引価格 / bitFlyer の価格ページ）。価格ページを選ぶと「価格ページを開く」ボタンと短い案内が出る（ほかのカードは使わない）。ボタンで専用ブラウザの価格ページが開き、価格が表示されてから「残高を取得」を押すと、表を自動で読んで価格に使う。取得後、Lightning の市場がある通貨について、ページの価格・Lightning の価格・差（参考）の表を折りたたみで出す。ページにない通貨は除外として示す（#103）。

## Coincheck Card

bitFlyer カードの次に置く。上から、API キーの権限の注意（残高の取得だけ。可能ならキーの利用元の IP アドレスを制限する）、キーとシークレットの入力と保存・削除、残高の取り込みの順。

- キーは保存後に再表示せず、保存済みかどうかだけを示す。
- 取り込みは bitFlyer と同じ手順（口座を選び、「残高を取得」、対応づけの結果を見て、「保有を置き換える」）。価格は公開ティッカーの最終価格だけで、基準の選択はない。JPY の通貨ペアがない通貨は除外として示す（#125）。

## GMO Coin Card

Coincheck カードの次に置く。上から、API キーの権限の注意（資産残高の参照だけ。取引・入出金は不要。可能なら IP アドレスを制限する）、キーとシークレットの入力と保存・削除、残高の取り込みの順。

- キーは保存後に再表示せず、保存済みかどうかだけを示す。
- 取り込みは Coincheck と同じ手順。結果の上に、価格の基準の注意を必ず出す。通常は「評価額は販売所の売値を使っています」。販売所の価格がなく取引所の最終約定価格で評価した銘柄（`basis` が `board`）があれば、その銘柄を名指しした注意を、エラーの色で足す。円のレートがない銘柄は除外として示す（#126）。

## Binance Card

GMO Coin カードの次に置く。上から、Binance Japan の利用者向けの注意（Binance Japan のキーがグローバル版の API で使えるのは未確認の前提であること。キーが拒否されたときは Binance のメッセージを出す）、API キーの権限の注意（読み取り専用。取引・出金などは付けない。可能なら IP アドレスを制限する）、キーとシークレットの入力と保存・削除、残高の取り込みの順。

- キーは保存後に再表示せず、保存済みかどうかだけを示す。
- 取り込みは Coincheck と同じ手順。結果の上に、価格の基準の注意を必ず出す: 「評価額は Binance の最終取引価格（取引所の板。販売所の価格ではない）を使っている」。JPY 市場がなく USDT 市場の価格に USDT/JPY を掛けた銘柄（`basis` が `board_via_usdt`）があれば、その銘柄を名指しした注意を、エラーの色で足す。換算できない銘柄は除外として示す。取得に失敗したときは、エラー文言（Binance の `code` と `msg`）の下に、上の前提の注意を再掲する（#128）。
- 「更新先の口座」は、前回選んだ口座を既定にする。

## Table Import Card

手入力の画面と同じ列に置く。上から、使い方の注意（証券会社には自分のブラウザでログインする）、取り込み元の名前（保存済みの名前を候補に出す）と値の通貨、ファイルの選択、貼り付け欄、プレビューと列の指定、結果の順。

- 取り込みの確認の画面は、評価額が 数量 × 価格 と通貨の最小単位を超えて合わない行（名前、読んだ評価額、計算した値）を、対応づけの下に注意として並べる（先頭 8 件。評価額が使われる。反映は止めない）。列の指定は、名前の列、評価額の取り方（1つの列、または数量 × 価格。価格の単位は 1 か 1 万）、見出しの行数、1件あたりの行数と、名前・数値がある行の位置、名前・数値・価格のセルの何番目の値か（空ならセル全体）、数値の前後の文字を許すか、記録する数量の列（評価額の列を選んだときだけ、任意）、更新する口座。値の通貨は、既定が「商品の通貨」で、選べば、別の通貨の商品に対応づけた行を除外する。取り込み元の名前に保存済みの指定があれば、読み込み後に自動で入れる。「列の対応を保存」で保存する。
- 「取り込みを確認」で、対応づけ済みの行、未対応の名前（商品を選んで対応づける）、除外した行とその理由を出す。bitFlyer と同じ部品を使う。

## Browser Fetch Section

「表の取り込み」カードの中の折りたたみ（「ブラウザで取得（任意）」）。ブラウザが見つからないときは、見つからない旨だけを出す。

- ブラウザ（Chrome・Edge・Brave のうち見つかったもの）、プロファイルのフォルダ（空なら既定）、「ブラウザを開く」「ブラウザを閉じる」（取得レシピのカードと同じ部品 `browser-controls.ts`。最後に開いたブラウザとフォルダが選ばれる）。開いたあとに、ページの選択と「ページを更新」「表を取得」、表の選択と「この表を使う」を出す。
- ページは「ホスト — タイトル」で示す（アドレス全体は出さない）。表は「行数 × 列数: 先頭のセルの文字」で示す。
- 「この表を使う」で、ファイルや貼り付けと同じ、列の指定の画面に進む。

## Fetch Recipes Card

「表の取り込み」のカードの次に置く。

- カードの説明の段落のすぐ下に「すべて取得」を置く（通常の流れの単一の操作）。一覧は 1 つの表（内容の幅の列を左に詰める: 名前、口座、取得のボタン、削除）で、「すべて取得」「このサイトを取得」「取得」（行のボタン。ホバーで「このレシピだけ取得」）は同じ取得の列に置いて左端をそろえ、幅も同じにする。ボタンの文字は折り返さない。小見出しは小さく、同じ行の取得の列に「このサイトを取得」を置く。狭い幅では一覧が横にスクロールする。
- 保存したレシピは、サイト（`start_site`）ごとの小見出し（プリセットが言う会社名。なければサイトのホスト）の下に並べる。小見出しの右に「このサイトを取得」（そのサイトのレシピをまとめて 1 回で取得する。同じサイトのレシピは同じログインとブラウザを使う）。サイトのないレシピは「そのほかのページ」にまとめて最後に置く（#117）。
- レシピの行は短くする: 名前、口座の選択、「このレシピだけ取得」、削除（2回のクリック）。名前は一覧と追加の選択で同じもの（組み込みのレシピはプリセットのラベル）。組み込みのレシピには「組み込み」のバッジを付ける。バッジと「i」アイコンは名前の列の右端にそろえる（名前は左）。行き先の説明（プリセットの説明、または たどるリンク › 表の書き出し（通貨））は、名前の横の「i」アイコンのホバーとキーボードのフォーカスで出す。「自分のレシピにする」は置かない（コピーは編集できず、使い道がないため）。アプリにないプリセットを指すレシピは、エラーの文と削除だけを出し、取得の対象に入れても、そのレシピの失敗として示す。レシピがないときは、作り方を案内する。
- 行の口座の選択を変えると、そのレシピの口座を替える（`SetRecipeAccount`。検証は Rust で、元に戻せる）。同じプリセットが先にある口座へは替えられない（行は元の口座に戻り、理由を出す）。
- 一覧の最後に、小見出し「プリセットから追加」（サイトの小見出しと同じ見た目）と追加の行を、一覧と同じ表に置く: プリセットの選択は名前の列（名前は一覧と同じ）、口座の選択（末尾に「新しい口座…」）は口座の列、単一の「追加」は削除ボタンの列（幅も同じ）。「新しい口座…」を選んだときだけ、口座の名前の欄が同じ行の取得ボタンの列（「追加」のすぐ左）に現れ、口座を作ってからレシピを追加する（常設の「口座を追加」は置かない）。選んだプリセットの説明を下に出す。プリセットの選択は「---」（未選択）で始まり、すでにレシピとして追加したプリセット（どの口座のものでも）は出さない。残りがなければ「---」だけで、選択も「追加」も使えない。口座の選択も「---」で始まり、重複の制限はない。「追加」は、プリセットと口座（または名前を入れた「新しい口座…」）を選ぶまで使えない。同じプリセットを同じ口座へもう一度追加すると、Rust が断る（最後の防壁）。
- すべてのレシピは「始めるページのサイト」を持つ（保存のときに必須。Rust が空を断る）。取得は、そのサイトの開いているページを自分で選んで読む。読むページの選択は置かない。古い版が保存したサイトのないレシピは、読み込みを壊さずに残し、小見出し「サイトなし」の下に、取得を使えなくして、削除して保存し直す案内とともに出す（自動では消さない）。
- ログイン: 取得を始めたとき、レシピが読むサイトのタブが開いていなければ、ブラウザが開いていなければ開き（選ばれたブラウザとフォルダで）、そのサイトのログインのページを新しいタブで開き、「自分でログインしてから、もう一度『取得』を押してください」と案内して、そのサイトのレシピは取得しない（ブラウザが前回のタブを復元してログインのページが「すでに開いている」場合も同じ。ほかのサイトは続ける）。案内は「開いたブラウザでログインしてから、もう一度『取得』を押してください」だけで、エラーは出さない。最初のリンクが見つからずに失敗したときは、そのエラーの文に「ログインしていない可能性があります」の案内を添える。「ログインのページを開く」のボタンは置かない。ログインのページが分からないサイトは、その旨と、自分でログインしてページを開くことを案内する。アプリは移動するだけで、入力もクリックもしない。
- 小見出し「ブラウザの設定」の下に、「ブラウザで取得」と同じ部品のうち、ブラウザの選択とプロファイルのフォルダ（入力欄は、案内の文字が全部見える幅まで広がる）だけを置く（#98。「ブラウザを開く」「ブラウザを閉じる」は置かない。ブラウザは取得が必要なときに自分で起動し、アプリの終了時に閉じる。開く・閉じるの操作は「ブラウザで取得」のカードにある）。見つかったブラウザがないときは、見つからない旨だけを出す。選んだブラウザとフォルダは、ブラウザを起動したときに覚え、再起動後も両方の場所で選ばれた状態になる（覚えていたブラウザが見つからなければ、見つかった最初のもの）。
- ブラウザのページ（ホスト — タイトル）の選択、「ページを更新」、「すべて取得」。
- 実行中の状態、注意が要るレシピ（行き先の違う同名のリンクが複数あるときの選択、保存したリンクが変わったときの選び直し、失敗の理由）、各レシピの結果（取り込みと同じ、対応づけ済み・未対応・除外の表示。ここに置換のボタンはない）、最後に、反映先の口座の一覧と「口座に反映する」（2回のクリック）。
- 「表の取り込み」のカードの中に「レシピとして保存」（名前、レシピが読むサイト（必須）、たどるリンクを1行に1つ、表の書き出し、リンクをたどってよいサイト（任意。確認済みのサイトだけ））がある。
