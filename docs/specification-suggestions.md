# Specification: Suggestions

[specification.md](specification.md) の一部。リバランスの計算と提案モードを扱う。

## Rebalance Calculation

`crates/rebalance` の `propose(holdings, targets, params)` が計算する。

- 入力: 保有（銘柄と評価額）、目標配分（銘柄と 0〜1 の比率）、パラメータ（追加投資額 `contribution`、許容乖離 `tolerance`）。
- 基準額: 保有の合計に `contribution` を足した額。銘柄ごとの目標額は「比率 × 基準額」。
- 提案: 目標額と現在額の差を `delta` とし、正なら Buy、負なら Sell。
- 保留: 現在の比率が目標比率から `tolerance` 以内なら Hold（`delta` は 0）。
- 目標にない銘柄は目標比率 0 として扱い、全量売却の提案になる。保有にない銘柄は現在額 0 として扱う。
- 検証: 目標比率の合計は 1（誤差 0.000001 まで許容）、各比率は 0〜1、銘柄の重複・負の金額・負の許容乖離はエラー。
- 金額は十進数で正確に計算し、丸めは行わない。演算はすべて桁あふれを検査し、panic せず `Overflow` エラーを返す（IPC 経由の入力でアプリが異常終了しないため）。丸め（最小売買単位など）は呼び出し側の責務。
- 結果は銘柄名の昇順。

## Suggestion Modes

保有タブの副タブ「リバランス」の「すべて」のタブと、口座ごとのタブの、どちらにも次の 4 つを出す。「すべて」は全口座をまたいで（下の All Tab）、口座のタブはそのタブの口座で計算する。

| モード | 内容 |
|---|---|
| 定額追加 | 入力した金額 X を、売らずに配る。目標を最も下回るカテゴリから順に、目標に届くまで足し、全部が届いたら残りを目標比率で按分する。カテゴリの中では、商品比率に同じ考え方を使う |
| 売らずに達成する追加額 | 売却なしで目標に届く最小の総額（各カテゴリの「現在額 ÷ 目標比率」の最大値）と、カテゴリごとの不足額 |
| フル・リバランス | 今の総額のまま、売りと買いで目標に合わせる。売買は依頼した口座の中だけで行い、ほかの口座の保有額は動かさない前提（チェックは口座のタブと別に持つ。「すべて」では、加わる全口座の中で売り買いする）。売れるかどうかは、その口座の設定に従う |
| 定額売却 | 入力した金額 Y を、目標を最も上回るカテゴリから順に売る。売れるのは売却してよい口座だけ |

- 対象口座に、足りないカテゴリの商品がなくて調整できない場合は、「実行できない」と理由を表示する。
- 許容乖離（これ以内なら提案しない幅）は、カテゴリが 1 ポイント、商品が 0 を既定とし、設定で変えられる。
- 提案額は、口座ごとの丸め単位に丸め、丸めたあとの合計が指定額に合うように、端数の大きい商品から 1 単位ずつ配り直す（最大剰余法）。
- 個別株は金額だけを提案する（株数は、株価と単元株数の入力が要るため扱わない）。
- 外貨は、商品に通貨を持たせ、為替は USD/JPY を 1 欄で手入力する。株価と為替の自動取得はしない。

### Calculation Details

実装は `crates/suggest`。評価額はすべて JPY に換算し（JPY と USD のみ対応。USD は手入力のレートで換算）、正確な十進数で計算する。1 兆円を超える金額と、大きすぎる比率は、桁あふれを避けるため受け付けない。

- **水位配分**: 比率が目標を最も下回るものから順に足し、足す額が増えると、次に低いものが加わる。全部が加わると、残りは目標比率で按分される。売らない。カテゴリで配分したあと、カテゴリ内の商品にも同じ方法で配る。
- **商品の比率**: 商品の比率（重み）は商品ごと、実行するモードごとの設定（`Portfolio::product_shares`、[specification-data.md](specification-data.md) の Product Shares）で、計算は実行するモードの比率だけを使う。0 より大きい相対比率で、設定のない商品は 1（等分）。モードの間の同期はしない。配る前に商品が全口座で持っている額を数え、目標を最も下回る商品から足す（購入額を均等に割らない）。売るときは、比率に対して多すぎるものから売る。
- **配り方**（`Request.method`。提案の入力で選ぶ。既定は `follow_portfolio`）: 2 つある。**ポートフォリオに従う**（`follow_portfolio`）は、ここまでの説明どおり、カテゴリの目標でカテゴリに配り、そのカテゴリの中を商品の比率で配る。**商品の比率で配る**（`by_product_weights`）は、カテゴリの目標を使わず（目標の合計が 1 でないなどの不備があっても止めない）、買う候補のすべての商品が、カテゴリをまたいで、比率の合計に対する自分の比率の割合（比率 ÷ 比率の合計）を目標とする。つまり商品どうしを、カテゴリを介さずに水位配分する。商品の候補、売買に加えない商品（口座のタブは `excluded`、「すべて」は `excluded_all`）、保有している商品だけを買う制限（`held_only`）、売却してよい口座・レコード、口座への配りと丸めは、ポートフォリオに従う場合と同じ。戦略を指定した口座のタブは、配り方によらず、その口座の戦略で計算する。
  - **定額追加**: 目標を最も下回る商品から足す（候補の商品の保有額に、足した額を加えた合計を、比率で配った額が各商品の目標）。**売らずに達成する追加額**: 候補の各商品の「保有額 ÷ 目標の割合」の最大値（と候補の保有額の合計の大きいほう）を水準とし、その差を必要額とする。比率が大きすぎる商品などで届かない分は商品ごとの注記（`ProductNotFilled`）にする。**フル・リバランス**: 候補の保有額の合計を比率で配った額が各商品の目標で、許容乖離（商品の許容乖離）の外にある商品を、買う側は不足額まで、売る側は超過額と売れる額までで売り買いし、総額は小さいほうに揃える。揃わない分は商品ごとの注記にする。**定額売却**: 目標を最も上回る商品から売る。
  - 結果にカテゴリの行は付かない（目標がないため）。ポートフォリオに従う場合の「カテゴリ内の入れ替えは提案しない」という制限はなく、カテゴリをまたぐ入れ替えも、同じカテゴリの商品どうしの入れ替えも、フル・リバランスで提案する。
  - 口座内の商品バランス（口座のタブの下段の表）は、配り方によらず、カテゴリ内の比率で表示する。
- **カテゴリ内の方向**（ポートフォリオに従う場合）: 1 つのカテゴリは、1 回の提案で買うか売るかのどちらか一方だけ（同じカテゴリの商品を買いながら別の商品を売ることはしない）。カテゴリ内の入れ替えは提案しない。買えない商品（売買に加えない、保有がない）と、売れない商品（売買から除く、保有がない、売れない種別だけ）は配分から外し、残りの商品が額を引き受ける。
- **売買から除く商品**: 口座の「売買に加えない」商品（`excluded`）は、どのモードでも買わず、売らない。保有額は、カテゴリの現在額と全体の合計には数える（カテゴリの目標との差は、除いた商品を含めて見る）。除いた商品しかないカテゴリは、買う候補も売る候補もないカテゴリとして扱い、実現できない分は注記する。リバランスのタブの商品一覧は、全商品に「売買に加える」チェックを付けて出し、ここで切り替える（Account Tabs）。
- **売却**: 水位配分の符号を反転した計算で、目標を最も上回るものから売る。1 つの商品について、その口座の保有額を超えて売らない。目標が 0 のカテゴリは、先に売り切る。
- **売らずに達成する追加額**: 各カテゴリの「現在額 ÷ 目標比率」の最大値を目標の総額とし、その差を必要額とする。使う額は、必要額を口座の丸め単位に切り上げた額。口座が買えないカテゴリがあるときは、足りない額を注記する。目標が 0 のカテゴリが価値を持っていると、売らずには達成できないのでエラーにする。
- **フル・リバランス**: 依頼した口座の中だけで行う（「すべて」では加わる全口座で行う）。許容乖離の内側のカテゴリは動かさない。売りは、売却してよい口座の保有額と、目標を超えた額までに制限し、買いは、口座が買えるカテゴリで、目標までに制限する。売りと買いの総額は、小さいほうに揃え、丸め単位に切り下げる。実現できなかった分は注記する。**カテゴリ内の商品どうしの入れ替え（カテゴリの合計は目標どおりで、商品の構成だけがずれている場合）は、まだ提案しない。**
- **丸め**: 商品ごとの額を口座の丸め単位の倍数にし、合計が指定額（または揃えた総額）にぴったり合うようにする（最大剰余法）。売りでは、保有額を超える丸めをしない。商品ごとの保有額は丸め単位の倍数にならないことがあり、売れるのは商品ごとに保有額を丸め単位に切り下げた額までなので、売却できる額（固定額の売り・フル・リバランスの売り側の上限）はこの切り下げた額の合計で数える。配り直す単位は、余裕のある商品（売りは保有額の範囲、買いは口座が買える商品）にだけ置く。足りなければ、固定額の売りはエラー、フル・リバランスは売り側の上限を下げて売り買いの総額を揃える。買い・売りとも、丸めたあとの合計は指定額（フル・リバランスは揃えた総額）と一致する。売らずに達成する追加額は決まった合計がなく、必要額の切り上げた額を使う。
- **表示の丸め**（#68）: 画面に出す金額は、通貨の最小単位に丸める（JPY は小数 0 桁、USD は 2 桁、ほかは ISO 4217 の小数桁。表にない通貨はそのまま。0.5 は 0 から遠いほうへ丸め、USD の `10.5` は `10.50` と桁をそろえる）。対象は、保有の評価額（商品の通貨）と、全体の合計・カテゴリ・グループ・口座・保有の評価額、口座内のバランス、提案の金額（JPY は整数の円）で、数量・単価・比率・重みは丸めない。丸めは表示専用で、Rust の関数（`portfolio::round_for_display`）が行い、フロントエンドは渡された文字列を表示するだけである。計算・保存・提案の計算・割合・エクスポートは丸める前の正確な値を使い、保存や編集で丸めない（編集欄は正確な値を開く）。保有の評価額は `PortfolioView::shown_values`、JPY の金額は応答に出す形（`serde`）で丸める。丸めた金額どうしの和は、丸める前の和と 1 円ずれることがある。
- 提案は、ポートフォリオを変更せず、保存もしない。提案をブロックする不備（`issues`）が残っているときは、計算せずにエラーにする。

### All Tab

「すべて」のタブは、口座を選ばず、全口座をまたいで提案する（`Request.account` が `None`）。実装は 1 口座の計算を口座の集合に広げたもので、口座のタブ（1 口座）は同じ計算の特別な場合。

- **加わる組**: 買う候補は、口座の `excluded`（「すべて」の提案では `excluded_all`）にない、（「保有のみ」のとき）その口座で保有している商品。売る候補は、売却してよい口座（口座の設定と、レコードの種別）の、除かれていない、保有のある商品。画面の「すべて」は、全口座の商品一覧を「口座」の列つきの 1 つの表にまとめ、行ごとにチェックを持つ（「すべて選択」「すべて解除」は表に出ている行の口座それぞれに働く）。表に出ていない商品の除外は、そのまま残る。
- **配分**: カテゴリと商品の水位配分は、今までどおり全口座の合計額で行う。商品に配られた額は、その商品を買える口座に、その口座の保有額が少ないほうから（等しい比率の水位配分）、売る額は売れる口座に、売れる額に比例して配る。
- **丸め**: 口座ごとの丸め単位が違うときは、提案の総額を口座の丸め単位の最小公倍数（小数の単位でも厳密に求める。大きすぎて求められなければエラー）に切り下げる。売れる額は、口座ごとにこの最小公倍数に切り下げて数え、足りなければフル・リバランスは取引を小さくして注記する。口座ごとの合計をまず最小公倍数の倍数に丸め、各口座の中の額をその口座の単位に丸める。売りは、（口座, 商品）の保有額を超えない。
- **結果**: 商品の行は口座を持ち、画面は口座ごとにまとめて出す。売れる口座がひとつもなければ「売却できない」エラー。
- 旧「全体リバランスの対象口座」はなくなった（スキーマ 17）。

### Account Strategy

口座は戦略を持つ。`ポートフォリオに従う`（既定。ここまでの説明）か、`商品と比率を指定`（`Strategy::Products`。商品の一覧と、手で入力した相対比率。空欄は等分）。実装は `crates/suggest/src/strategy.rs`（配り方の「商品の比率で配る」は `engine.rs`）。

- 指定した口座のタブでは、カテゴリの目標を使わない。指定した商品の合計（その口座の保有額。除いた商品を含む）を比率で配った額が各商品の目標で、保有額との差が不足（正）・超過（負）。目標は 1 円単位に丸め、合計が合うよう最大剰余法で端数を配る。指定した商品は、保有がなくても一覧に出す。指定にない商品は、表にも提案にも出ず、買わず、売らない。
- 4 つのモードは、既存の水位配分と丸めを、指定した商品に対して使う。**定額追加**: 比率を最も下回る商品から足す。**売らずに達成する追加額**: 各商品の「保有額 ÷ 比率」の最大値を水準とし、その差を必要額とする。**フル・リバランス**: 許容乖離（商品）の外にある商品を、比率に合わせて売り買いする。売りは、売却してよい口座・レコードの保有額と超過額まで、買いは買える商品の不足額までで、売りと買いの総額は小さいほうに揃える。揃わない分は商品ごとの注記（`ProductNotFilled`）にする。**定額売却**: 比率を最も上回る商品から売る。売れない口座は「売却できない」エラー。
- 売買から除く商品（`excluded`）は、目標の計算（合計）には数えるが、買わず、売らない。「保有している商品だけ買う」の制限（`held_only`）は、一覧が利用者の選択なので、この口座では適用しない（保有のない指定商品も買える）。
- 提案の結果にカテゴリの行は付かない。ポートフォリオの目標の問題（目標の合計など）は、この口座の提案を止めない。
- 「すべて」のタブでは、戦略を指定した口座は加わらない（買いも売りもしない）。その口座の戦略は、その口座のタブで効く。保有額は全体の合計とカテゴリの現在額には数える。

### Account Tabs

口座ごとのタブ（「リバランス」の副タブの、「すべて」以外のタブ）は、「すべて」と同じ並びで 2 段に構成する。

- 上段: 提案（4 つのモード、金額、結果）。そのタブの口座で計算する。全体のカテゴリ目標から見て、この口座の売買をこの口座で扱える商品にどう配るかを示す。
- 下段: 口座内の商品バランス（保有の一覧。商品比率に対する現在額と、足りない額・多い額）。「すべて」のタブも、対象口座について同じ表を出す。

主口座以外のサブ口座は、売却できない設定のことが多く、そのときはフル・リバランスと定額売却は「売却できない」と表示するか、買いだけの結果になる。

実装は `suggest::account_balance`（読み取り専用の `get_account_balance` コマンド）と、`suggest_rebalance`。

- 戦略を指定した口座では、下段は指定した商品の表（上の Account Strategy）で、カテゴリの見出しはない。
- 下段は 1 つの商品一覧で、口座のタブと「すべて」は同じ部品（「すべて」は口座の列つきで全口座を 1 つの表にする）。上段の入力の下に見出しなしで置く。切り替え「すべて表示」（既定）/「売買に加えるものだけ」を持つ。「すべて表示」は、その口座で保有している商品だけを出し（保有のない商品は候補にしない）、各商品に「売買に加える」チェックボックス（`excluded` の裏返し）を付け、「すべて選択」「すべて解除」を置く。「売買に加えるものだけ」はチェックした商品だけをチェックボックスなしで出す。表の下の注記で、チェックの意味と、保有している商品だけを出すことを説明する。口座の「売却可」と丸め単位もこのタブで編集する。
- 下段の計算は、カテゴリごとに、その口座の保有額の合計を、口座が保有する商品に、商品の目標の持ち方に従って配る。どのモードの設定を使うかは**定額追加**の設定で決める（表はひとつで、モードごとには出さないため）。商品の比率（設定のない商品は 1）で分ける。売買に加えない商品も、保有していればこの表に出て、カテゴリの合計に数える。保有していない商品は、一覧に行は出るが数字は出さない。
- 目標と不足額は、1 円単位に丸める。カテゴリ内の目標の合計がカテゴリの合計に一致するよう、最大剰余法で端数を配る。不足は正、超過は負。
- カテゴリの間でのお金の移動は、この表では扱わない（提案の役割）。
- **保有していない商品**: その口座で保有していない商品は、買う候補にしない。商品一覧の「すべて表示」には行を出す（チェックはできる）が、現在額・目標・不足の数字は出さず、「売買に加えるものだけ」でもチェックしていれば出る。「保有している」は、その口座のレコード（種別を問わない。売却できない NISA などを含む）の評価額の合計が 0 を超えることで、数量 0 や比率だけのレコード（評価額 0）、レコードがない場合は保有していない。売買に加える商品でも、保有していなければ買わない。下段の表は、保有している商品だけにカテゴリの保有額を配る（比率の合計も保有している商品だけで取る）。提案は `Request::held_only`（既定は false。Rebalance の「すべて」を含む全タブが true で送る）で、買う候補を保有している商品に絞る。保有している商品のないカテゴリは買う候補がなくなり、「実行できない」として扱う。「すべて」でも、対象口座の提案の買う候補を同じ判定で絞る。新しい商品をその口座で買い始める提案はどのタブからも出ない（先に商品のレコードを追加するか、保有してから提案する）。
