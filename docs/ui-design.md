# UI Design

## Status

雛形の画面（Tauri のデモ）のみ。機能ごとの画面は未設計。

## Principles

[UI_GUIDELINES.md](dev-charter/UI_GUIDELINES.md) に従う。

- ライト・ダーク・システムの各モードに対応し、ユーザーが設定から選べるようにする。
- 配色: ライトは背景 `#FFFFFF`・文字 `#4e454a`・強調 `#000000`。ダークは背景 `#000000`・文字 `#bab1b6`・強調 `#FFFFFF`。
- システムカラーとネイティブ UI コンポーネントを優先し、テーマに合わせて CSS の `color-scheme` を設定する。
- Unicode の絵文字を UI パーツに使わない。アイコンは Google Material Symbols を第一選択にする。
- UI の文言は英語を開発言語とし、他言語は [LOCALIZATION_POLICY.md](dev-charter/LOCALIZATION_POLICY.md) に従って追加する。
- 表示と入力のみを扱い、計算や検証は Rust 側に置く。

## Dashboard Layout

メインウィンドウの上部に 3 つのタブを置く（保有 / 取り込み / 設定）。選んだタブはブラウザの保存領域に覚える（使えなくても動く）。タブは表示と非表示を切り替えるだけで、どのパネルも描画され続けるので、切り替えても入力は失われない。矢印キーでタブを移れる。

| タブ | 内容 |
|---|---|
| 保有 | 左の列に、全体のバランス（カテゴリ別の「目標 vs 現在」の棒グラフと、構成の円グラフ）と全体のリバランス提案、その下に口座ごとのタブ（口座内の商品バランスと、口座への追加の提案）を積む。残りの幅は、保有レコードの表が使う |
| 取り込み | 組み込みのレシピで取り込む手順（番号付き。1 と 2 は済・未を示す）、取得レシピ（口座をその場で作れる。取得は、すべて・1 つの口座・1 つのサイト・レシピ 1 つずつから選べる。失敗したレシピは、口座名と、開くべきページを示し、取れたレシピは残す）、表の取り込み（ファイル・貼り付け・ブラウザの表を、自分で列を選んで取り込む）、bitFlyer |
| 設定 | カテゴリ、商品、口座（上下の並び替え）、保有（手入力）、設定、データの保存場所 |

- 保有の表は、列が収まらないときは表の中で横にスクロールする（ほかのパネルの幅には影響しない）。幅が約 1000px 以下では、左の列と表が縦に並ぶ。
- 表のまとめ方は「カテゴリ別」と「口座別」を切り替えられる。カテゴリ別には、小計の行（評価額、比率）を付ける（目標と差は表に出さない）。口座別は、口座ごとに商品を並べ（2 列目にカテゴリを出す）、見出しの行に口座の評価額と比率を出す（Rust の `get_overview` の口座ごとの合計）。
- 評価額がなく比率だけを持つ記録（これから買う商品）には、金額の横に「評価額はまだありません」と出す。
- 古い版のデータファイルは、読み込まずにそのまま残す。画面の上に、新しく始めるには portfolio.json をデータの保存場所から別の場所へ移し、アプリを開き直すことを案内する。
- 数字は 3 桁区切りで、円の単位を明示する。不足と超過は、符号と色で示し、色だけに頼らない。
- グラフはライブラリを使わず、SVG と CSS で自前で描く。最初は棒グラフと円グラフだけで、資産の推移（履歴）は、保存の仕組みと一緒にあとで追加する。
- 「全体リバランスの対象口座」は、左パネルの提案の近くで 1 つ選べる。
- 画面の文言は、英語のキーで持ち、英語（フォールバック）と日本語の 2 言語で提供する。カテゴリ名や商品名は、利用者が入れる値なので翻訳しない。
- フロントエンドは素の TypeScript で作り、表示と入力だけを扱う。計算は Rust 側が行う。

## Overall Balance Panel

保有タブの左の列の上。

- カテゴリごとの「目標 vs 現在」の横棒グラフ（目標は枠線、現在は塗り）と、現在の構成の円グラフを、SVG で描く。凡例にカテゴリ名と比率を文字で出し、色だけに頼らない。
- 評価額と比率は Rust の `get_overview` が返す。フロントエンドは図形の位置を決めるためだけに `Number` を使い、表示する文字は Rust の十進数の文字列から作る。
- 対象口座（全体リバランスの対象口座）を選び、提案の種類（定額追加・売らずに達成する追加額・フル・リバランス・定額売却）と、必要なら金額を入れて「提案する」を押すと、`suggest_rebalance` の結果をカテゴリ別の増減と対象口座での売買として表示する。増減は符号を付けて示す。
- 編集のたびにグラフを更新し、前の提案は消す（数字が変わっているため）。

## Holdings Panel

保有タブの表。

- 保有レコード（口座 × 商品）を、カテゴリごと（または口座ごと）にまとめて並べる。切り替えは「まとめ方」の選択で行う。各グループの先頭に小計の行を置き、評価額と全体に占める比率を出す。目標と目標との差は表に出さない（データと全体のバランスのパネルには残す）。
- 1 レコードは 1 行。列は、商品（名前の欄だけ）、口座（カテゴリごとのときだけ）、カテゴリ（選択。商品を別のカテゴリへ移す入口）、金額、数量、価格、評価額、比率。長い名前は欄の中で省略記号で切り、隣の欄にはみ出さない。
- 保有タブのパネルは重ならない。広い窓では、左の列（全体のバランスと口座ごと）と表を横に並べ、約 1000 px 以下では縦に積む（表は全幅）。カードは自分の列の幅を超えて広がらない。
- 金額の欄はその場で編集でき、商品の通貨で入力する。空にすると、その保有を削除する。確定の流れは手入力画面と同じ（Enter かフォーカス移動で 1 つの編集として送る）。
- 円換算の評価額と比率は Rust の `get_overview` が返す。編集のたびに全パネルで 1 回だけ取得し直す。
- カテゴリの見出しの行の名前と、各商品の行の名前・カテゴリは、その場で編集できる（下の「カテゴリ」「商品」のカードと同じ編集。カテゴリを変えると、商品は新しいカテゴリのグループへ移る）。
- 保有のない商品の行は出さない。新しい保有は、手入力画面の保有の表から追加する。

## Account Tabs Panel

保有タブの左の列の下。

- 口座ごとに 1 つのタブを持つ。矢印キーでタブを移れる。
- 上段「口座内の商品バランス」は、口座が持つカテゴリごとに、商品の現在額と、商品比率が求める額、不足（+）か超過（-）かを示す。比率を求めないカテゴリ（自由・現在の比率を維持）は、現在額だけを示す。
- 下段「この口座への追加」は、定額追加と、売らずに達成する追加額を、このタブの口座で計算する（対象口座の選択とは独立）。売却を伴う 2 つのモードは出さない。
- 提案の入力欄と結果の表示は、全体のバランスのパネルと同じ部品（`src/views/suggestion.ts`）を使う。

## bitFlyer Card

手入力の画面と同じ列に置く。上から、API キーの権限の注意（資産残高の取得だけ）、キーとシークレットの入力と保存・削除、残高の取り込みの順。

- キーは保存後に再表示せず、保存済みかどうかだけを示す。
- 取り込みは、口座を選んで「残高を取得」を押し、対応づけの結果（対応づけ済みの表、未対応の通貨ごとの商品の選択、除外される通貨）を見てから「保有を置き換える」を押す。口座の選択肢は、暗号資産の口座を先に並べる。

## Table Import Card

手入力の画面と同じ列に置く。上から、使い方の注意（証券会社には自分のブラウザでログインする）、取り込み元の名前（保存済みの名前を候補に出す）と値の通貨、ファイルの選択、貼り付け欄、プレビューと列の指定、結果の順。

- 列の指定は、名前の列、評価額の取り方（1つの列、または数量 × 価格。価格の単位は 1 か 1 万）、見出しの行数、1件あたりの行数と、名前・数値がある行の位置、名前・数値・価格のセルの何番目の値か（空ならセル全体）、数値の前後の文字を許すか、記録する数量の列（評価額の列を選んだときだけ、任意）、更新する口座。値の通貨は、既定が「商品の通貨」で、選べば、別の通貨の商品に対応づけた行を除外する。取り込み元の名前に保存済みの指定があれば、読み込み後に自動で入れる。「列の対応を保存」で保存する。
- 「取り込みを確認」で、対応づけ済みの行、未対応の名前（商品を選んで対応づける）、除外した行とその理由を出す。bitFlyer と同じ部品を使う。

## Browser Fetch Section

「表の取り込み」カードの中の折りたたみ（「ブラウザで取得（任意）」）。ブラウザが見つからないときは、見つからない旨だけを出す。

- ブラウザ（Chrome・Edge・Brave のうち見つかったもの）、プロファイルのフォルダ（空なら既定）、「ブラウザを開く」。開いたあとに、ページの選択と「ページを更新」「表を取得」、表の選択と「この表を使う」、「ブラウザを閉じる」を出す。
- ページは「ホスト — タイトル」で示す（アドレス全体は出さない）。表は「行数 × 列数: 先頭のセルの文字」で示す。
- 「この表を使う」で、ファイルや貼り付けと同じ、列の指定の画面に進む。

## Fetch Recipes Card

「表の取り込み」のカードの次に置く。

- 保存したレシピの一覧（名前、たどるリンク › 表の書き出し → 口座（通貨））と削除（2回のクリック）。レシピがないときは、作り方を案内する。
- 組み込みのレシピ（プリセット）の選択、口座の選択、「追加する」。選んだプリセットの説明（どのページから始め、何を読むか）を下に出す。
- レシピに「始めるページのサイト」があれば、「すべて取得」は、そのサイトの開いているページを自分で選んで読む（ページの選択は、サイトのないレシピだけに使う）。
- 「ログインのページを開く」: レシピが読むサイトのログインのページを、ブラウザの新しいタブで開く（ログインは利用者が自分で行う）。
- 口座が 1 つもないときは、組み込みのレシピの追加を使えなくして、「先に口座を追加してください」と案内する。
- ブラウザのページ（ホスト — タイトル）の選択、「ページを更新」、「すべて取得」。
- 実行中の状態、注意が要るレシピ（行き先の違う同名のリンクが複数あるときの選択、保存したリンクが変わったときの選び直し、失敗の理由）、各レシピの結果（取り込みと同じ、対応づけ済み・未対応・除外の表示。ここに置換のボタンはない）、最後に、反映先の口座の一覧と「口座に反映する」（2回のクリック）。
- 「表の取り込み」のカードの中に「レシピとして保存」（名前、たどるリンクを1行に1つ、表の書き出し、リンクをたどってよいサイト（任意。確認済みのサイトだけ））がある。

## Data Folder Card

設定タブの、設定のカードの次に置く。

- 今のデータの保存場所（このコンピューターだけか、選んだフォルダか）を示す。フォルダのフルパスを入れて「このフォルダを使う」、iCloud Drive が使えるコンピューターでは「iCloud Drive のフォルダを使う」、選んだ後は「このコンピューターのフォルダに戻す」。
- 移す先にすでにデータがあるときは、「そのフォルダのデータを使う」かキャンセルかを聞く。
- 同期が作った競合のコピー、未ダウンロードのファイル、使えなかった新しいファイルは、画面の上に知らせる。

## Manual Entry Screen

設定タブにある画面で、カテゴリ・商品・口座・保有・設定を手入力する。

- 1 列に、カテゴリ、商品、口座、保有（商品 × 口座の表）、設定のカードを並べる。表は、カードの中で横にスクロールできる。
- 入力欄は、値を確定したとき（Enter かフォーカス移動）に 1 つの編集として Rust へ送る。保存に成功すると、表示を更新する。失敗したときは、理由を表示し、入力欄を元の値に戻す。保存のあとも、フォーカスと Tab の順は保たれる。
- 比率は「%」で入力し、Rust には正確な小数（例: 30 → 0.3）で送る。計算には浮動小数点を使わない。
- 削除は 2 回のクリックで実行する（1 回目で確認の表示に変わり、数秒以内の 2 回目で削除する）。`window.confirm` は Tauri の WebView で信頼できないため使わない。
- 提案をブロックする不備（カテゴリの合計が 100% でない、など）は、画面の上に一覧で出す。
- 言語は、英語と日本語を切り替えられ、選んだ言語はブラウザの保存領域に覚える。保存領域が使えなくても動く。
