# UI Design

## Status

雛形の画面（Tauri のデモ）のみ。機能ごとの画面は未設計。

## Principles

[UI_GUIDELINES.md](dev-charter/UI_GUIDELINES.md) に従う。

- ライト・ダーク・システムの各モードに対応し、ユーザーが設定から選べるようにする。
- 配色: ライトは背景 `#FFFFFF`・文字 `#4e454a`・強調 `#000000`。ダークは背景 `#000000`・文字 `#bab1b6`・強調 `#FFFFFF`。
- システムカラーとネイティブ UI コンポーネントを優先し、テーマに合わせて CSS の `color-scheme` を設定する。
- Unicode の絵文字を UI パーツに使わない。アイコンは Google Material Symbols を第一選択にする。
- UI の文言は英語を開発言語とし、他言語は [LOCALIZATION_POLICY.md](dev-charter/LOCALIZATION_POLICY.md) に従って追加する。
- 表示と入力のみを扱い、計算や検証は Rust 側に置く。
- 金額は、通貨の最小単位に丸めた文字列を Rust から受け取って表示する（JPY は整数、USD は小数 2 桁）。保有の評価額、合計、小計、口座内のバランス、提案の金額が対象で、数量・単価・比率は丸めない。丸めは表示だけで、編集欄は正確な値を開き、閉じても保存値は変わらない。フロントエンドは数値に変換せず、桁（末尾の 0 を含む）を文字列のまま保つ。

## Dashboard Layout

メインウィンドウの上部に 3 つのタブを置く（保有 / 取り込み / 設定）。選んだタブはブラウザの保存領域に覚える（使えなくても動く）。タブは表示と非表示を切り替えるだけで、どのパネルも描画され続けるので、切り替えても入力は失われない。矢印キーでタブを移れる。

| タブ | 内容 |
|---|---|
| 保有 | 左の狭い列に、全体のバランス（カテゴリ別の「目標 vs 現在」の棒グラフと、構成のドーナツグラフ）だけを置く。残りの広い領域は、副タブ（保有 / リバランス）で切り替える: 「保有」は保有レコードの表、「リバランス」は口座のタブ（先頭の「すべて」が全体のリバランス提案で、対象口座の選択と結果を持つ。以降は口座ごとに、口座の商品一覧と、口座への追加の提案）。提案の結果の表は広い領域に出るので、左の列からあふれない |
| 取り込み | 組み込みのレシピで取り込む手順（番号付き。1 と 2 は済・未を示す）、取得レシピ（口座をその場で作れる。取得は、すべて・1 つの口座・1 つのサイト・レシピ 1 つずつから選べる。失敗したレシピは、口座名と、開くべきページを示し、取れたレシピは残す）、表の取り込み（ファイル・貼り付け・ブラウザの表を、自分で列を選んで取り込む）、bitFlyer、Coincheck、GMO コイン、Binance |
| 設定 | グループ、カテゴリ、全レコード（商品とレコードの編集）、口座（上下の並び替え）、設定、データの保存場所 |

- 副タブの選択は、ブラウザの保存領域に覚える（使えなくても動く）。主タブと同じく表示と非表示を切り替えるだけで、データの更新や言語の切り替えのあとも、選んだ副タブのままになる。矢印キーで副タブを移れる（選択の判断は `src/subtabs.ts`）。廃止した副タブ「提案」「口座ごと」の保存値は、「リバランス」として読む。
- 保有の表は、列が収まらないときは表の中で横にスクロールする（ほかのパネルの幅には影響しない）。幅が約 1000px 以下では、左の列と広い領域が縦に並ぶ。
- 最初のウィンドウは 1280 × 800（左の列と広い領域が横に並ぶ幅）で、最小は 720 × 520。画面の作業領域より大きいときは、作業領域に収める（`preventOverflow`）。大きさは保存しない（起動のたびにこの大きさになる）。
- 表のまとめ方は「カテゴリ別」「口座別」「種別ごと」を切り替えられる。「種別ごと」は、種別（種別のない記録は「未設定」）ごとに記録を並べ、見出しの行に種別の評価額と比率を出す（Rust の `get_overview` の `types`）。「表示する種別」の選択で、1 つの種別（または種別のない記録）だけを表示できる。絞り込み中は、小計の行は全体の値になってしまうので、値を空にする。カテゴリ別には、小計の行（評価額、比率）を付ける（目標と差は表に出さない）。口座別は、口座ごとに商品を並べ（2 列目にカテゴリを出す）、見出しの行に口座の評価額と比率を出す（Rust の `get_overview` の口座ごとの合計）。
- 評価額がなく比率だけを持つ記録（これから買う商品）には、金額の横に「評価額はまだありません」と出す。
- 古い版のデータファイルは、読み込まずにそのまま残す。画面の上に、新しく始めるには portfolio.json をデータの保存場所から別の場所へ移し、アプリを開き直すことを案内する。
- 数字は 3 桁区切りで、円の単位を明示する。不足と超過は、符号と色で示し、色だけに頼らない。
- グラフはライブラリを使わず、SVG と CSS で自前で描く。最初は棒グラフと円グラフだけで、資産の推移（履歴）は、保存の仕組みと一緒にあとで追加する。
- 「全体リバランスの対象口座」はない（スキーマ 17 で廃止）。「リバランス」の副タブの「すべて」のタブは、全口座をまたいで提案する。
- 保有タブの副タブは「一覧」と「リバランス」。「一覧」「リバランス」のパネルは、先頭の見出しを持たない（タブの名前が見出しの代わり）。
- 画面の文言は、英語のキーで持ち、英語（フォールバック）と日本語の 2 言語で提供する。カテゴリ名や商品名は、利用者が入れる値なので翻訳しない。
- フロントエンドは素の TypeScript で作り、表示と入力だけを扱う。計算は Rust 側が行う。

## Overall Balance Panel

保有タブの左の列の上。

- カテゴリごとの「目標 vs 現在」の横棒グラフ（目標は枠線、現在は塗り）と、現在の構成のグラフを、SVG で描く。凡例にカテゴリ名と比率を文字で出し、色だけに頼らない。
- グループが 1 つでもあるときの構成のグラフは二重のドーナツにする: 内側がグループ、外側がカテゴリ（グループの順に並べ、同じグループのカテゴリは、グループの色の濃淡で示す）。グループに属さないカテゴリは、内側の「グループなし」（灰色）に 1 つにまとめる。グループがないときは、カテゴリだけの円グラフにする。凡例は、グループの行（現在の比率 / 目標の比率。目標はカテゴリの目標の合計）の下に、そのカテゴリを字下げして並べる。
- 評価額と比率は Rust の `get_overview` が返す。フロントエンドは図形の位置を決めるためだけに `Number` を使い、表示する文字は Rust の十進数の文字列から作る。
- 全体のバランスのパネルには、グラフだけを置く。提案は「保有」タブの副タブ「リバランス」に移した（結果の表が左の狭い列に収まらなかったため）。
- 「リバランス」の副タブ（`src/views/rebalance.ts`）の先頭のタブ「すべて」では、提案の種類（定額追加・売らずに達成する追加額・フル・リバランス・定額売却）と、必要なら金額を入れて「提案する」を押すと、`suggest_rebalance` の結果をカテゴリ別の増減（表）として表示し、商品ごとの増減は下の商品一覧に出す（下の Account Tabs Panel）。増減は符号を付けて示す。
- 編集のたびにグラフを更新し、前の提案は消す（数字が変わっているため）。

## Holdings Panel

保有タブの表。表示だけで、入力欄はない（商品名、カテゴリ、金額、カテゴリとグループの名前の編集は、設定タブの「全レコード」で行う）。

- 保有レコード（口座 × 商品 × 種別）を、カテゴリごと（または口座ごと）にまとめて並べる。切り替えは「まとめ方」の選択で行う。各グループの先頭に小計の行を置き、評価額と全体に占める比率を出す。カテゴリ別でグループがあるときは、カテゴリの小計の上に、グループの小計の行（太い罫線。グループなしのカテゴリは「グループなし」の行）を置く。目標と目標との差は表に出さない（データと全体のバランスのパネルには残す）。
- 1 レコードは 1 行。列は、商品、口座（カテゴリごとのときだけ）、種別（独立した列。種別のない記録は空欄。口座ごとのときは商品の右）、カテゴリ、価格（単位つき。商品の通貨を付ける）、数量、評価額（保存した値。3 桁区切りと商品の通貨）、評価額（円）、比率。長い名前は省略記号で切り、隣の欄にはみ出さない。
- 保有タブのパネルは重ならない。広い窓では、左の列（全体のバランス）と広い領域（副タブ）を横に並べ、約 1000 px 以下では縦に積む（広い領域は全幅）。カードは自分の列の幅を超えて広がらない。
- 円換算の評価額と比率は Rust の `get_overview` が返す。編集のたびに全パネルで 1 回だけ取得し直す。
- 表の上（見出しの横）と「保有がまだありません。」の空の状態に、「全レコードで編集」のボタンを 1 つ置く。押すと設定タブへ切り替え、全レコードのカードまでスクロールして、絞り込み欄にフォーカスする（行ごとの編集ボタンはない）。設定で名前・カテゴリ・金額を変えると、表は作り直される。
- 保有のない商品の行は出さない。新しい保有は、全レコードのカードから追加する。

## Account Tabs Panel

保有タブの副タブ「リバランス」（`src/views/rebalance.ts`）。

- 口座のタブを並べ、先頭は「すべて」（英語 UI では All）。以降は口座ごとに 1 つ。矢印キーでタブを移れる。選んだ口座がなくなったら「すべて」に戻る。
- 全タブが同じ並び: 上に提案の入力（種類 4 つ・金額・「提案する」）と結果、下に商品一覧（見出しは付けない）。口座のタブは、その口座の一覧を 1 つ。「すべて」は全口座の一覧を 1 つの表にまとめ、「口座」の列を足す（口座の設定は表の下の折りたたみにまとめる）。提案は、口座のタブはその口座、「すべて」は全口座をまたぐ。
- 商品一覧は 1 つの部品。表示の切り替え「すべて表示」/「売買に加えるものだけ」（タブごと。既定は「すべて表示」）を持つ。「すべて表示」は、その口座で保有している商品だけを（保有のない商品は候補にしない。口座によって扱えない商品も多いため）、カテゴリごとにまとめて並べ、各商品に「売買に加える」チェックボックス（口座のタブは `excluded`、「すべて」は `excluded_all` の裏返し。2 つは別で、互いに影響しない）と現在額を出し、「すべて選択」「すべて解除」を置く。「売買に加えるものだけ」は、チェックした商品だけをチェックボックスなしで並べる。表の下に、チェックの意味（外した商品は売買せず、保有額はカテゴリに数える）。「すべて」では、同じ商品が複数の口座で保有されていれば口座ごとに行を出す。戦略を指定した口座は「すべて」に加わらないを注記する。保存してから提案に使い、保存中は操作を止める。
- 一覧には「目標」「不足 / 超過」の列を出さない（提案の「増減」「提案後」だけで見る）。
- 売りが同じ口座の商品の複数の種別にまたがるときは、商品の行の下に種別ごとの行（種別名・現在額・増減・実行後）を出す。詳細は [specification-suggestions-accounts.md](specification-suggestions-accounts.md)。
- 商品一覧の「比率」の列（戦略を指定した口座の一覧には出さない）は、提案の入力で選んでいる提案の種類の、商品の比率（重み）を、商品ごとの数値の入力欄で編集する（0 より大きい数。既定は 1 を表示する。0 以下や数でない入力は拒否して元に戻す）。提案の種類を切り替えると列はその種類の比率に変わり、一覧の上の注記に今の種類を書く。比率は、配り方が「ポートフォリオに従う」ではカテゴリの中の商品の間で、「商品の比率で配る」ではすべての商品の間で効く。設定は商品ごと・種類ごと・タブごとで、口座のタブの欄はその口座のタブの比率、「すべて」のタブの欄は「すべて」の比率を編集する（互いに独立）。編集すると提案の結果は消える。
- 提案の入力には、提案の種類の下に「配り方」の選択（「ポートフォリオに従う」、「商品の比率で配る（カテゴリをまたぐ）」）を置く。「すべて」のタブも口座のタブも同じ。保存はせず、その場の選択として提案の要求（`method`）に載せる（金額や種類と同じ扱い）。「商品の比率で配る」の結果にはカテゴリの表を出さず、注記だけを出す（商品ごとの増減は商品一覧に出す）。
- 口座の「売却可」と丸め単位は、リバランスのタブで編集する。口座のタブでは提案の入力の上に、「すべて」では口座ごとの枠の先頭に置く。
- 口座のタブでは、その口座で保有していない商品は「対象外」とし、表にも提案にも出さない。「すべて」でも、その口座で保有していない商品は、その口座の買う候補にしない。保有の判定は [specification-suggestions-accounts.md](specification-suggestions-accounts.md) の Account Tabs に従う。
- 商品と比率を指定した口座（戦略）のタブは、下段が「指定した商品の現在額」（カテゴリの見出しはない）で、上段の提案はカテゴリの表を出さず、注記だけを出す（売買は下段の表に出す）。「すべて」のタブでは、その口座の枠に「独自の戦略があり、ここには加わらない。その口座のタブを使う」と注記する（一覧はその口座の指定商品を出す）。
- 提案の結果があるとき、商品一覧に「増減」と「実行後」の列を足す（結果が消えると列も消える。どのタブ・表示でも同じ）。売買のある行は符号つきの増減と、Rust が返す実行後の額（`ProductLine.after`）を出し、売買のない行は増減を空にして実行後を現在額と同じにする。カテゴリの見出しの行は空欄。行のない商品の売買は表の下に出す。結果は、提案の部品が結果を消すとき（タブの切り替え、保有の変更、エラー）に一緒に消える。
- 一覧は、口座が持つカテゴリごとに、商品の現在額を示す。
- 売却を伴う種類（フル・リバランス、定額売却）は、そのタブの口座の売却設定に従う。売れない口座では Rust の理由を表示する。
- 全タブで提案の部品（`src/views/suggestion.ts`）は 1 つで、口座の選び方（`src/rebalance-account.ts`）だけがタブで変わる。

## Remembered Account on Exchange Cards

bitFlyer、Coincheck、GMO コイン、Binance のカードで「更新先の口座」に最後に選んだ口座を、取引所ごとに覚えて次回の初期値にする（再起動後も。詳細は [specification-import.md](specification-import.md) の Remembered Account for Exchange Cards）。覚えた口座が消えていれば、暗号資産の口座を先頭にした従来の並びの 1 番目になる。

## Import Link Step (#131)

bitFlyer、Coincheck、ブラウザの取得、表の取り込みは、同じ部品（`src/views/import-plan.ts`）で、別名のない名前を商品に対応づける。

- 同じ名前（前後の空白と大文字小文字を無視）の商品があれば、その行の「対応づける」の選択で最初から選んでおく。似た名前の商品（規則は [specification-import.md](specification-import.md)）がある行は、左に線を付けて強調し、名前の隣に情報アイコン（取得レシピのカードと同じ見た目で、ホバーとキーボードのフォーカスで文を出す）を置き、似た商品の名前を示す。どちらも、選択肢の先頭にその商品を置く。クリックするまで対応づけない。
- 対応づけや「商品を作って対応づける」が拒否されたら、理由をその行の下にエラー色で出す（画面上部の状態表示にも出る）。同名の商品がすでにあるときは、読める文にして、その商品を選んでおく。
