# Specification: Storage and Export

[specification.md](specification.md) の一部。[specification-data.md](specification-data.md) から切り出した、保存（Storage）とエクスポート（Export）を扱う。

## Storage

保存と編集は `crates/portfolio`（モデル・検証）と `src-tauri`（ファイル）で実装済み。

- スキーマのバージョンは 25（25 で商品の比率を記録ごとにした: `product_shares` の項目に記録の `account` と `account_type` を足し、旧 `account` は口座のタブを表す `tab` に改め、`SetProductShare` も同じ形にした。古いアプリは商品の比率として読むので断る。古い版のファイルは、読み込むときに、各タブで商品の比率を、そのタブの範囲にある記録の比率に分けて、合計が元の比率になるようにする（`migrate.rs`）: 記録の評価額に比例して分け、評価額 0 の記録があるときは等分する。比率 1 になる記録は保存しない。そのタブに記録のない商品の項目は捨てる）。24 では（24 で口座のタブごとの商品の比率を足した: `product_shares` の項目に `account`（なし = 「すべて」のタブの比率）を足し、`SetProductShare` に `account` を足した。古いアプリは全項目を「すべて」の比率と読み、口座のタブの比率を無視するので断る。古い版のファイルは、読み込むときに、既存の項目を「すべて」の項目として残し、口座ごとにも複製する（`migrate.rs`）ので、どのタブの結果も変わらない）。23 では（23 で標準の種別の売却可否の上書き `type_sellable_overrides` を足した。古いアプリは上書きを無視して、許したものを売らず、止めたものを売ってしまうので断る。古い版のファイルは上書きなしで読む（変換するものはない）。`get_portfolio` の結果には、標準の種別ごとの今の売却可否 `builtin_type_sellable` を足した）。22 以前の経緯は [specification-data-versions.md](specification-data-versions.md) にある。
- 保存先は、アプリのデータディレクトリの `portfolio.json`。所有者だけが読める権限（Unix は 0600）で作り、10 MiB を超えるファイルは開かない。
- アプリ名は「Robo Advisor」、識別子は `y.marui.Robo-Advisor`（`src-tauri/tauri.conf.json`。Swift 系の `y.marui.<App-Name>` に揃えた）。データディレクトリとブラウザの専用プロファイルの既定の場所は、識別子で決まる（macOS は `~/Library/Application Support/y.marui.Robo-Advisor`）。キーチェーンのサービス名は識別子とは別の `dev.marui.robo-advisor` のままにしている（識別子を変える前に保存したキーを見つけるため。変えない）。
- ID は数値で、再利用しない。古い参照が別のものを指すことがない。
- **保存先の選択（#35）**: 保存先のフォルダは設定で選べる。OS が同期するフォルダ（iCloud Drive など）を指せば、複数のコンピューターでデータを共有できる。同期は OS の仕事で、アプリは何も送らない。選んだフォルダは、ローカルのアプリのデータフォルダに置く小さな `data-location.json`（コンピューターごとの設定）に覚える。フォルダは絶対パスで `..` を含まないこと。使えない選択は、ローカルのフォルダに戻す。
  - **移すとき**: 移す先に `portfolio.json` がなければ、今のデータをそこへ複写する。すでにあるときは、利用者の確認のあとにそのファイルをそのまま使う。もとのファイルは、バックアップとしてそのまま残す。ローカルのフォルダへ戻すこともできる。
  - **古い版で上書きしない**: ファイルに `revision`（受け付けた編集の回数）を持つ。編集の前に、ディスクの版が新しければ先にそれを取り込み、保存の直前にもう一度確かめて、その間に新しい版が保存されていたら保存せず、読み込み直したうえで操作をやり直すよう伝える。ディスクの版が自分より古いとき（バックアップの復元など）は、新しい方として上書きする。ウィンドウに戻ったときと `get_portfolio` のたびに、新しい版があれば取り込む。
  - **同期の問題を隠さない**: 同期が作る競合のコピー（`portfolio 2.json` など）と、まだダウンロードされていないファイル（`.portfolio.json.icloud`）は、画面の上に知らせる。読めないファイルは、これまでどおり上書きしない。
  - **フォルダの切り替えと編集の競合（#43）**: データの場所が変わるたびに増える番号 `data.location`（`PortfolioView` の `data`）を持つ。`apply_portfolio_edit` は、画面を描いた表示の `location` を一緒に受け取り、今の番号と違えば、編集を適用せずに断る（フォルダを切り替える間に送られた編集が、ID が 1 から始まる別のデータに当たるのを防ぐ）。フォルダの切り替えは、取得した行（実行結果）も無効にする。
  - 保有資産は機密情報なので、同期するフォルダは利用者が信頼できる場所を選ぶ。ブラウザ取得の専用プロファイルは同期しない（ローカルのまま）。
- フロントエンドは `get_portfolio`（現在の状態と、提案をブロックする不備の一覧 `issues`）と、`apply_portfolio_edit`（1 つの編集 `Edit`）のほか、読み取り専用の `get_overview`（グループごと・カテゴリごと・記録ごと・口座ごとの評価額と比率。グループごとの項目は、グループが 1 つもなければ空で、あれば、グループの順に並べ、グループなしのカテゴリがあるときだけ最後に `group: null` の項目を足す。目標の比率は、属するカテゴリの目標の合計）、`get_account_balance`（口座内の商品バランス）と `suggest_rebalance`（提案）を使う。検証・ID の採番・保存は Rust が行い、保存に成功してからメモリを更新する。
- 読み込んだファイルは信頼せず、毎回、バージョン・ID の重複・参照・値の範囲を検査する。読めないファイルは、上書きせずにエラーを返し、編集も受け付けない。
- 口座は作成時に売却可で、レコードは種別の売却可否（初期値では NISA・旧NISA の種別は売らない）に従う。


目標、口座、商品、別名、保有、列の対応づけは、アプリのデータディレクトリに JSON ファイルを 1 つ置いて保存する。

- スキーマのバージョンを持つ。
- 書き込みは、一時ファイルを作ってから置き換え、書きかけのファイルを残さない。
- 保有資産は機密情報なので、ログやエラーメッセージに値を出さない。暗号化は OS のディスク暗号化に任せる。API キーだけは、従来どおり OS のキーチェーンに置く。
- 資産の推移の履歴を追加する段階で、SQLite への移行を再検討する。

## Export

他の解析ソフト（表計算や統計ソフトなど）で使えるように、全データを書き出せる。画面の「エクスポート」ボタンで実行する。

- 書き出し先は、ダウンロードフォルダの中の新しいフォルダ `tauri-robo-advisor-export-<日付>-<時刻>`（UTC。同じ秒の 2 回目は `-2`、`-3`…）。既存のフォルダやファイルは上書きしない。場所と名前はアプリが決め、画面から指定することはできない。
- フォルダは所有者だけが読める権限（Unix は 0700、ファイルは 0600）で作る。資産情報を含むので、画面に注意を表示し、README にも書く。
- ファイル: `holdings.csv`（記録 1 行ずつ。商品・口座・種別（`account_type`: 既定の種別の id、追加した種別は名前、未設定は空）・カテゴリ・グループの情報と、JPY 換算額、全体に占める割合）、`groups.csv`（グループごとの目標の合計、評価額、割合）、`categories.csv`（グループの列を含む）、`products.csv`、`aliases.csv`、`product_targets.csv`（記録の比率。`mode`・`tab_account_id`（空は「すべて」のタブ）・`account_id`（記録の口座）・`account_type`（記録の種別。`holdings.csv` と同じ表記、未設定は空）・商品・カテゴリ・`relative_weight`。比率 1 の商品は行がない）、`accounts.csv`（売買から除く商品は `excluded_product_ids`）、`settings.csv`、`portfolio.json`（アプリの形式での全データ）、`README.txt`（列の説明、バージョン、日時）。
- CSV は UTF-8（BOM つき）、改行は CRLF で、Excel でも文字化けしない。金額と比率は、アプリ内の正確な十進数のまま書き（画面の表示用の丸めはしない）、割合は小数 6 桁に丸める。比率は 1 を基準にした小数（0.25 は 25%）。
- JPY への換算ができない値（為替レートが未設定、JPY と USD 以外の通貨）は空欄にする。その値を含む合計と割合も空欄にし、一部だけの合計を出して誤解させない。
- 利用者が入力した名前が `=`、`+`、`-`、`@` で始まると、表計算ソフトが数式として実行しうる。そのため、名前は先頭にアポストロフィを付けたテキストとして書く。
